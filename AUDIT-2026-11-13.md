# Audit, 13 Nov 2026 (AutoTune 2.30.1)

The app, its UI and UX, the process flow, and the link between the phone and AutoTune on a TV or a Windows PC.

How it was done: from the code, the docs, the Windows window renders (`./gradlew :desktop:shots`) and the store screenshots. There was no Android SDK in that session, so the phone and TV screens were not rendered or run. `:dsp`, `:link` and `:desktop` tests passed (89, 6 and 22).

The TV and the Windows app never talk to each other. Each is a server the phone connects to, one at a time, so "the connection" means phone to TV and phone to PC.

Status: every item was open when this was written. Mark an item "done in X.Y.Z" when it is fixed.

## Connection: phone to TV or PC

Ordered by how much each would hurt in use.

1. **Stop on the phone does not stop the TV or PC.** `stop()` only cancels the phone's job (`TheatreViewModel.stop`). Only the level test sends `quiet`, so a stopped distances, EQ or EQ-check test keeps playing its sweeps to the end, with the EQ held off.
2. **A dropped link mid-test is reported as a volume problem.** Tests never check that the link is still open. A pass ends with "The start beeps were not heard: turn the volume up" (`measurePassAsIs`), and the level test listens to silence for up to 180 s per speaker (`levelTest`).
3. **A dead link is noticed slowly, or never.** The phone's ping gets no answer and neither side has a read timeout (`LinkServer.serve` sets `soTimeout = 0` after the hello). If the TV loses power the phone can show "connected" for minutes. The TV shows a vanished phone as connected until another pairs, which also blocks Pretend (`TvViewModel.setPretend`).
4. **The phone's screen can switch off while measuring.** Only the TV screen sets keep-screen-on (`TvActivity`). A multi-seat EQ test, the level test or a 5-spot car reading can run past the screen timeout.
5. **The companion keeps playing when the phone goes.** Level noise loops for up to two minutes; nothing stops on disconnect (`TvViewModel` and `PcEndpoint`, `onPhone`).
6. **The pairing code is weak.** Four digits, never changed. The 1.5 s pause applies per connection and connections are unlimited, so anyone on the Wi-Fi can try all 10,000 in seconds (`LinkServer.serve`). The damage is bounded: test sounds and an EQ clamped to +6 dB.
7. **The address and announcement are set once at start.** If the PC or TV starts before the network is up, or its address changes, the phone never finds it (`desktop Main.kt`, `TvViewModel` init). A failed TV registration is ignored (`announce`).
8. **Connect by address assumes port 47810** (`TheatreViewModel.connectAddress`). The server falls back to any free port when that one is taken, and the PC window shows the address without the port.
9. **Reconnects can collide.** The page, the retry loop and the widget all call `CompanionLink.ensure()` with no lock, and every `LinkClient.connect` starts by closing the current link.
10. **The TV is reachable only while its screen is open.** The server lives in the TV screen's view model, so the phone widget cannot toggle the EQ once the TV app is closed. The PC stays reachable from the tray.
11. **"Sent" is not confirmed.** `useEq()` logs and saves the EQ as sent even when the link is closed (`LinkClient.send` drops it silently); nothing tells the user. A stale EQ error is also never cleared by a later good `eqstate`.
12. **Windows firewall is unverified.** HANDOVER already lists it. The code adds no firewall rule, so a refused prompt most likely leaves the PC unreachable.

The link module has six tests, none for drops, timeouts or stopping.

## Process flow

- **The home-theatre branch leaves the guided flow.** After "Yes, AutoTune is on the TV" the five-step header disappears and the user lands on three unordered test cards. This follows the owner's "no nagging about levels" note, but a first-time user gets no order at all.
- **Names are asked before the connection is tried.** If pairing fails, the typed names sit waiting.
- **Set up shows two counters at once**: "Step 1 of 5" and "2 of 4".
- **The step bar jumps 1, 3, 5**, because Stock and Verify have no page.

## UI

- **Windows:** the EQ key says "press for on" when there is no EQ and it is disabled.
